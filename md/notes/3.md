# Oracle Database

Oracle Database is a ***relational database management system (RDBMS)*** developed by Oracle Corporation.

## Oracle Virtual Private Database (VPD)

Oracle Virtual Private Database (VPD) is a security mechanism that allows to restrict access to database objects to be restricted ***at the row level***.

VPD associates ***access control policies*** with database objects. When a user issues a query, the policy can dynamically determine which rows the user is allowed to access based on ***user or session attributes***.

\bigskip

> ***Features***

The main features of VPD are:

- **Fine-Grained Access Control (FGAC):** Access to data can be restricted ***at row level***, rather than only at the level of entire tables or objects.
- **Attribute-Based Access Control (ABAC):** Access decisions can depend on ***user/session attributes***, such as the user identity or the time at which the request is issued.
- **Dynamic policies:** The access condition can be ***dynamically determined*** according to the characteristics of the requesting user or session. The ***policy function*** can be implemented as a PL/SQL function, which is then attached to the protected table.
- **Transparent enforcement:** The policy is applied to queries ***accessing the protected object***, so users see only the rows they are authorized to access.

The combination of FGAC and ABAC allows VPD to define and enforce ***row-level access control policies based on attributes***.

## Oracle Vault

Oracle Database Vault is a security mechanism designed to protect sensitive data ***even from highly privileged database users***.

\bigskip

> ***Purposes***

The main purposes of this database mechanism are:

- ***Restrict access of highly privileged users*** to sensitive database objects.
- ***Enforce Separation of Duty***, so that different administrative responsibilities can be separated.
- Provide some ***support for ABAC and FGAC*** to some extent.
- Support ***security and compliance requirements***, e.g. GDPR. 

A key motivation is that mechanisms such as VPD mainly protect ordinary users, whereas a DBA ***may be able to bypass VPD policies***.

\bigskip

> ***Features***

The main features of this system are:

- **Realm:** A ***protected zone of the database*** containing selected database objects and roles. Access to the objects inside the realm is ***controlled separately***, so even a user with powerful database privileges cannot automatically access them.
- **Authorization:** The process of ***granting or denying access*** to a realm based on the user's identity, role, or other attributes.
- **Ruleset:** A set of rules that ***define the conditions under which access*** to a realm is granted or denied. Rulesets can be ***based on various factors***, such as user identity, time of day, or IP address.

The combination of these features ***supports ABAC and FGAC***.

\bigskip

> ***Commands***

The main commands for managing Oracle Database Vault are:

- `CREATE_REALM`: Creates a new realm in the database.
- `ADD_OBJECT_TO_REALM`: Adds a database object (e.g., table, view, procedure) to a specified realm.
- `ADD_AUTH_TO_REALM`: Adds a user or role to a specified realm. Optional, you can also specify a ruleset to define the conditions for access.
- `CREATE_RULE`: Creates a new rule that defines the conditions for access to a realm.
- `CREATE_RULE_SET`: Creates a new ruleset that can contain multiple rules.
- `ADD_RULE_TO_RULE_SET`: Adds a rule to a specified ruleset.

These commands ***build the foundation*** for implementing Oracle Database Vault.
