# Data Privacy

Privacy is the right of individuals to ***control their personal information***, including how it is **collected, stored, and shared**, while protecting their ***Personal Identifiable Information (PII)***.

## Offline Privacy

Offline privacy concerns the protection of individuals' privacy when ***microdata are shared*** with a third party. Mainly, there are ***two approaches*** to protect privacy:

- **Non-interactive:** Release a ***sanitized version*** of the data.
- **Interactive:** Provide a ***query interface*** to the data, allowing users to access information without exposing the raw data.

\bigskip

> ***Attribute Classification***

Attributes in a dataset can be classified into ***three categories:***

- **Identifiers:** Directly identify an individual.
- **Quasi-Identifiers (QI):** Attributes that can identify individuals when combined with external information.
- **Sensitive attributes:** Private information that the data publisher wants to protect.

An example of a dataset with these attribute classifications ***is shown below:***

| **Identifier** | **Quasi-Identifier** | **Sensitive Attribute** |
| - | - | - |
| **NameSurname** | **BirthDate** | **Disease** |
| - | - | - |
| John Doe | 01-01-1980 | Cancer |
| Jane Smith | 02-02-1990 | Diabetes |

### $k$-anonymity

A released table ***satisfies k-anonymity if*** every combination of QI values occurring in the released table occurs in at least $k$ records.

1. Therefore, each record ***is indistinguishable*** from at least $\geq k-1$ other records with respect to the quasi-identifiers.
2. These $k$ records form an ***equivalence class***.
3. Links attacks cannot be performed with a confidence **greater than*** $> \frac{1}{k}$.

To achieve achieve k-anonymity is necessary to apply ***two techniques:***

- **Generalization:** Replace specific QI values with ***less specific values*** until at least $k$ records have identical QI values.
- **Suppression:** Remove records when generalization would cause ***excessive information loss***.

\bigskip

> ***Limitations***

$k$-anonymity does not guarantee protection against ***attribute disclosure:***

- **Homogeneity attack:** All records in an equivalence class have the same sensitive attribute value.
- **Background knowledge attack:** An attacker can use external information to infer sensitive attribute values.

That is the reason why $k$-anonymity was extended to $l$-diversity, which requires that each equivalence class has at least $l$ distinct values for the sensitive attribute.

This approach addresses the problem of homogeneous sensitive values, but can still suffer from ***skewness attacks*** and ***similarity attacks***.

### $m$-invariance

A sequence of generalized tables $T(1), \ldots, T(n)$ is ***$m$-invariant*** if and only if:

- Every table $T(1), \ldots, T(n)$ is **$m$-unique**.
- Each individual **has the same signature** in every generalized table in which they appear.

A generalized table $T(j)$ is **$m$-unique** if and only if:

- Each QI-group in $T(j)$ contains at least **$m$ tuples**.
- All tuples within the same QI-group have **distinct sensitive values**.

### Differential Privacy

Differential privacy protects against the additional ***risk caused by the participation*** in the database.

Let $D$ and $D'$ be two datasets differing from at most one tuple. Let $Q$ be a query answering algo, and let $Q(D)$ be the result returned by $Q$ when executed on dataset $D$. $Q$ satisfies $\epsilon-\text{differential privacy}$ if for any possible
output $o$:

$$
\frac{Pr[Q (D) = o]}{Pr[Q(D') = o]} \leq e^\epsilon \sim (1 + \epsilon)
$$

To achieve achieve differential privacy, ***some techniques*** can be applied:

- Output perturbation
- Input perturbation
- Perturbation of intermediate values
- Perturbation during training

\bigskip

> ***Types***

Two main types of differential privacy are:

- **Local:** Provides ***stronger privacy*** guarantees, as the data is perturbed before being sent to the server.
- **Central:** Provides ***higher utility***, as the server can apply more sophisticated techniques to the raw data before perturbation.

## Online Privacy

Online privacy concerns the protection of personal data ***throughout the information life cycle***, from collection to storage, use, and destruction. The main framework for online privacy in the EU is the ***GDPR (General Data Protection Regulation)***. 

### General Data Protection Regulation (GDPR)

The GDPR regulates the different stages of the ***information life cycle:***

1. **Capture:** What data can be collected, how they can be collected, and what the individual ***must be informed about***.
2. **Store:** How and where ***data can be stored*** and how they ***must be protected***.
3. **Use:** Data can only be used for ***permitted and specified purposes***.
4. **Destroy:** Data should be kept only for the ***necessary period*** and then ***deleted***.

\bigskip

> ***Pillars***

The main pillars and techniques are:

- **Purpose limitation:** Data should only be used for ***specified and legitimate purposes***.
- **Data minimisation:** Only the ***necessary data*** should be collected and processed.
- **Accuracy:** Personal data should be ***accurate and kept up to date***.
- **Storage limitation:** Personal data should be retained for ***no longer than necessary***.
- **Lawfulness, fairness and transparency:** Personal data must be processed ***lawfully, fairly, and transparently***.
- **Integrity and confidentiality:** Personal data must be protected against ***unauthorized access, loss, or disclosure***.
- **Accountability:** Organizations must be able to ***demonstrate compliance*** with GDPR requirements.
